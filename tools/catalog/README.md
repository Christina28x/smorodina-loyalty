# Пробный сбор каталога Smorodina

Разбирает сохранённые HTML-карточки в JSON и локальный HTML для проверки. Не подключается к БД, не создаёт SQL и не меняет товары. Массовый обход сайта пока не реализован: сайт возвращает проверку браузера на автоматические запросы из рабочей среды.

## Запуск

Python 3.10 или новее:

```sh
python -m pip install -r tools/catalog/requirements.txt
python tools/catalog/extract.py "product.html" --output catalog-review
```

Можно передать несколько HTML-файлов. Для попытки скачать фотографии добавьте `--download-images`. Загрузка останавливается на первой ошибке; проверка браузера не обходится. Проверяются тип ответа, фактический формат и целостность изображения; HTML никогда не сохраняется под видом JPEG. Результаты остаются черновиком, даже если скачаны все изображения.

Откройте `catalog-review/review.html`. В `products.review.json` находятся поля, исходные ссылки, статусы скачивания и незаполненное согласование. Успешные изображения размещаются внутри `catalog-review/public/img/products/`. В JSON путь записывается без `public/`.

Парсер проверен на одной реальной карточке набора «Анти-акне контроль 3 в 1». Для других типов карточек селекторы нужно подтвердить на примерах. Отсутствующее поле остаётся null; это не команда стереть старое значение. Текущая и зачёркнутая цены сохраняются отдельно. HTML очищается от скриптов и атрибутов, полные тексты берутся из блоков «Подробнее» без удвоения видимого текста. Размеры фотографий сохраняются для проверки качества.

```sh
python -m unittest discover -s tools/catalog -p "test_*.py"
```

## Сохранение истории перед будущим импортом

1. Сделать у себя полную резервную копию БД со структурой и данными всех таблиц; проверить восстановление в отдельную тестовую БД. Присылать приватные данные или помещать дамп в GitHub не требуется.
2. Не удалять и не перенумеровывать старые товары. В текущей схеме удаление товара каскадно удаляет `order_items`, `favorites` и `product_images`.
3. Для действительно того же товара сохранять ID и локальный slug. Изменение названия/состава само по себе не доказывает, что это тот же товар. Сопоставления утверждать явно; для нового товара выделять новый ID.
4. До обновления названий предусмотреть снимок старого названия в позиции заказа: сейчас там есть `price_at_purchase`, но название кабинет читает из связанного текущего товара. Изменение подкатегории также влияет на рекомендации по старым покупкам.
5. Снятые с продажи товары в будущем скрывать отдельным признаком активности; его сейчас в схеме нет. Учесть каталог, серии, рекомендации, избранное и добавление в корзину. Не ставить глобальный фильтр, который скроет товар из истории заказов.
6. Будущий импорт должен работать транзакционно, по утверждённым соответствиям, с предварительной проверкой всех файлов, сохранением ID/slug/created_at, без обновления исторических цен покупок, бонусов и транзакций. Повторный запуск не должен создавать дубли.
7. Сравнить позиции заказов, цены покупок, балансы, уровни и суммы транзакций до и после. Файлы изображений готовить до транзакции; БД не может откатить операции файловой системы.

Это план следующего этапа, а не уже реализованный импорт. `migrate:fresh`, повторное восстановление старого каталога поверх нового и текущий ProductSeeder для обновления использовать не следует.

## Архивы, сохранённые браузером (основной рабочий путь)

```sh
python tools/catalog/archive_review.py face.zip promotions.zip --output catalog-review
```

Архивы содержат структуру `категория/подкатегория/папка_товара/HTML`. HTML может быть перемещён внутрь своей папки `_files`: инструмент разрешает ссылки по точному относительному пути либо точному имени файла только в той же папке товара. По всему каталогу изображения по имени не подбираются. Из архивов копируются только изображения основной галереи; сторонние скрипты не выполняются. Для просмотра откройте `catalog-review/index.html`.

Этот путь использует только обычную цену: зачёркнутую исходную, когда есть скидка, иначе текущую. Категории берутся из папок, а не canonical URL (включая `/novinki/`). Серия берётся только из явной метки линейки и пока сохраняется текстом; привязка к существующему `series_id` — отдельный этап. Объём берётся из поля страницы, а при его отсутствии — из явного окончания названия, например «90 г», с указанием источника `volume_source`. Отсутствующие значения не придумываются.

Проверено на двух предоставленных архивах: 70 товаров face и 26 promotions, 614 изображений. Поддержан альтернативный блок описания `js-detail-text_sphere`. Разные карточки объёмов сохраняются отдельно по исходной идентичности; создание нескольких товаров из единственной HTML-карточки с переключателем объёма пока не реализовано. Повторы исходного товара выводятся как ошибки, не перезаписываются молча.

### Уточнение согласованного плана БД

Пользователь выбрал новый каталог с новыми ID и переносом сохранённой учебной истории. Поэтому рекомендация выше сохранять старые ID не является выбранным планом. Перед заменой нужно подготовить и утвердить полную таблицу соответствий **всех** старых ID новым, включая численно совпавшие ID. Для отсутствующих аналогов согласуются замены. Исторические цены, суммы, количества, пользователи, бонусы и транзакции сохраняются; товарная аналитика отражает согласованные замены. Замена БД и перенос истории пока не реализованы и не запускались.
